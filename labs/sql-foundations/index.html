SQL Foundations: Querying for a Security Audit

Column selection, wildcard retrieval, and chronological ordering in a MariaDB security-analyst workflow.

MariaDBSELECTWildcard *ORDER BY

Task 1 — Device audit (column selection)

The machines table holds 200 devices. Progressively narrowing columns surfaced patch currency: device a184b775c707 on OS 1 had a patch date of 2021-09-01 — over four years stale, a priority for the update cycle.

sql
SELECT device_id, operating_system, OS_patch_date
FROM machines;

Task 2 — Login investigation (SELECT *)

Scanning log_in_attempts found no unexpected geographic logins, but flagged after-hours access — jrafael at 03:05 and bisles at 01:30 — warranting the filter-based follow-up in later labs.

Task 3 — Chronological ordering (ORDER BY)

A secondary sort key breaks ties within a date. ORDER BY login_date, login_time pinned the earliest event in the dataset to bsand at 00:19:11 on 2022-05-08 — where initial-access attempts often originate.

sql
SELECT * FROM log_in_attempts
ORDER BY login_date, login_time;

key takeaway

Even the most basic SQL has real security weight: which columns you pull, and in what order you view them, can be the difference between catching a threat early and missing it entirely.
