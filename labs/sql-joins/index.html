SQL Joins for Incident Investigation

Correlating siloed tables — machines, employees, login attempts — with INNER, LEFT, and RIGHT JOINs to trace compromised assets.

MariaDBINNER JOINLEFT JOINRIGHT JOINForeign keys

Several machines in the organisation had been compromised. The investigation needed a coherent picture built from three separate tables — machines, employees, and log_in_attempts — linked through shared columns.

Task 1 — Match employees to machines (INNER JOIN)

machines and employees share device_id. An INNER JOIN returns only rows matched in both tables — every machine definitively assigned to a known employee.

sql
SELECT *
FROM machines
INNER JOIN employees ON machines.device_id = employees.device_id;

Task 2 — Expose gaps (LEFT & RIGHT JOIN)

A LEFT JOIN returned every machine (NULL where no employee matched) — revealing at least one unassigned machine, a potential security flag. A RIGHT JOIN returned every employee, exposing lrodriqu (employee 1009) with no machine assigned.

Task 3 — Correlate logins (INNER JOIN on username)

Joining employees to log_in_attempts on username paired each staff profile with its login events — department, office, country, IP, and success flag in one view. 200 records returned.

key takeaway

INNER JOIN is the strictest match — ideal for confirmed asset-employee pairings. LEFT and RIGHT JOINs expose gaps: NULLs signal unassigned machines or employees without assets, both worth investigating. Together they form the foundation for cross-table forensic analysis.
