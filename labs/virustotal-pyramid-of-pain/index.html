VirusTotal Malware Investigation

A Tier 1 SOC investigation: one SHA-256 hash expanded across the Pyramid of Pain, from a rotatable MD5 up to privilege-escalation TTPs.

VirusTotalPyramid of PainMITRE ATT&CKThreat Intel

This project simulates a Tier 1 Security Operations Center (SOC) investigation at a financial services company. An employee received an email containing a password-protected spreadsheet attachment, with the password supplied in the body of the same email. After the employee opened the file, a malicious payload executed on the workstation, dropping multiple unauthorized executable files and triggering an intrusion detection system (IDS) alert. The SHA-256 hash of the retrieved malicious file served as the starting artifact for the investigation. Using VirusTotal, a crowdsourced threat intelligence platform that aggregates verdicts from dozens of independent security vendors, the file was analysed across its detection ratio, static properties, network relations, and sandboxed behaviour. The resulting indicators of compromise (IoCs) were then mapped onto the Pyramid of Pain, a framework that orders IoC types by the operational difficulty they impose on an adversary when a defender detects and blocks them — from trivially-replaceable hash values at the base to costly-to-alter tactics, techniques, and procedures (TTPs) at the apex.

Task 1 — Alert triage and timeline review

Before beginning the VirusTotal investigation, the alert details and the event timeline were reviewed to establish the sequence of compromise, and the SHA-256 hash of the malicious file was recorded as the artifact for analysis.

Task 2 — Detection tab: determining maliciousness

The Detection tab returned verdicts from 71 security vendors, of which 53 flagged the file as malicious — a ratio of roughly 75%. The Community Score, a crowdsourced maliciousness indicator drawn from the VirusTotal user base, stood at -292, a strongly negative score consistent with the vendor consensus. The popular threat label trojan.flagpro/fragtor, along with the family labels flagpro, fragtor, and bfrl, further corroborate a trojan classification rather than a false positive. With all three independent measures — vendor ratio, community score, and named threat classification — pointing in the same direction, the file is assessed as malicious.

Task 3 — Details tab: identifying an additional hash value

The Details tab provides the results of VirusTotal's static analysis and lists every hash type computed for the artifact. Beyond the SHA-256 hash already used as the case's starting point, the report also lists an MD5 and a SHA-1 hash, either of which is equally valid for uniquely identifying this specific file. The MD5 hash was selected for the Hash values tier of the Pyramid of Pain.

Task 4 — Relations tab: domain and IP address indicators

The Relations tab lists every domain and IP address the malware's sandboxed executions contacted, alongside a Detections column showing how many vendors flagged each one as malicious. Of the 100 contacted domains listed, the large majority returned 0/91 detections — legitimate infrastructure, such as Google and Microsoft services, that the malware likely queried incidentally. One domain, a.sinkhole.yourtrap.com, stood out with 10/91 detections, making it a credible malicious network indicator. Among the 431 contacted IP addresses, 104.86.245.126 was selected for the Pyramid of Pain despite carrying a 0/91 detection ratio — illustrating a core property of the Pyramid: IP addresses sit low on the pyramid precisely because they are cheap for an attacker to rotate and are frequently shared, legitimate, or coincidental infrastructure, which makes them weak indicators in isolation even when directly observed in the malware's own traffic.

Task 5 — Behavior tab: network artifacts, tools, and TTPs

The Behavior tab aggregates sandbox execution reports from multiple analysis engines — including CAPA, CAPE Sandbox, DAS-Security Orcas, Rising MOVES, and Tencent HABO — each observing the malware's actions when detonated in an isolated environment. Reviewing these reports surfaced a dropped file, KB0K8X6S.htm, logged as a host artifact; use of the Command Prompt (cmd.exe) and Windows Management Instrumentation (wmiprvse.exe) as execution tools; and three techniques mapped to the MITRE ATT&CK Privilege Escalation tactic (TA0004). These three indicator types sit progressively higher on the Pyramid of Pain than hashes, domains, or IPs, because a defender who detects and disrupts them forces the adversary to retool or rewrite part of the attack chain rather than simply rotating infrastructure.

Task 6 — Pyramid of Pain documentation

All identified indicators were consolidated into the Pyramid of Pain template, ordering the six IoC types by increasing cost-to-adversary: hash value (MD5) at the base, followed by IP address, domain name, network/host artifact, tools, and TTPs at the apex. This ordering reflects the difficulty a threat actor faces when each indicator type is detected and blocked — a hash is trivially defeated by recompiling the binary, while retooling an entire attack chain to avoid a known TTP demands significant adversary investment.

key takeaway

This investigation confirmed the retrieved file as malicious through three independent, mutually reinforcing signals: a 53/71 vendor detection ratio, a Community Score of -292, and a named trojan classification (flagpro/fragtor family). Beyond the initial SHA-256 hash, the VirusTotal report yielded a full spread of indicators across the Pyramid of Pain — from an easily-rotated hash and a low-confidence IP address, through a flagged malicious domain and a dropped host artifact, up to the tools and privilege-escalation TTPs that represent the adversary's actual tradecraft. The exercise reinforced why threat intelligence teams prioritise TTP-level detection over IoC-level blocklisting: indicators lower on the pyramid are cheap for an attacker to discard, while the behavioural patterns at the top are far more costly to change and therefore far more durable as detection signals.
