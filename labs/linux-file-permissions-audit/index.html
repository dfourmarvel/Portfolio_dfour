Auditing Linux File Permissions

The first formally documented lab: uncovering over-permissive files and hidden-file exposures, then locking them down with chmod.

ls -alchmodPermission stringsPrinciple of least privilege

Acting as an analyst auditing a research team’s Linux development environment, the task was to examine file and directory attributes for authorization vulnerabilities — over-permissive write access and hidden-file exposures — then bring everything into compliance using chmod.

Reading the permission strings

ls -al lists every file including hidden ones (the -a flag) alongside their permission strings (the -l flag). Each 10-character string breaks down as: type (d or -), then three groups of three — owner, group, others — each rwx.

bash
$ ls -al
ItemPermissionsIssue
project_k.txt-rw-rw-rw-others can write
.project_x.txt (hidden)-rw--w----group has write, no read
drafts (directory)drwx--x---group can enter and execute

Stripping public write access

Policy: no file should grant write access to "others." project_k.txt (-rw-rw-rw-) violated this outright. chmod o-w — o for others, - to remove, w for write — silently fixed it.

bash
$ chmod o-w project_k.txt
$ ls -l
# -rw-rw-rw- → -rw-rw-r--

Securing a hidden file

.project_x.txt started at -rw--w---- — the owner could read/write, but the group had write-only access (no read), and the target state required read-only access for both owner and group. Two commands got there: u-w removed the owner’s write, then g+r,g-w added group read and removed group write.

bash
$ chmod g+r,g-w .project_x.txt
$ ls -al
# -rw--w---- → -r--r-----

Locking down a directory

The drafts directory (drwx--x---) let the group execute — meaning enter and access contents — despite policy restricting it to the owner alone. Execute permission on a directory controls entry, so removing it with g-x locked the group out entirely.

bash
$ chmod g-x drafts
# drwx--x--- → drwx------

summary

Three targeted chmod operations brought the entire file structure into compliance: public write access stripped from project_k.txt, the hidden .project_x.txt reduced to read-only for owner and group, and the drafts directory isolated entirely to its owner. This was the first lab formally documented on the path to the Google Cybersecurity Professional Certificate.
