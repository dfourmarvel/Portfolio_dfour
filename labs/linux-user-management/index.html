Managing User Access in Linux

The full user lifecycle — provision, assign, expand, offboard — as an exercise in least privilege.

useraddusermodchownuserdelsudo

Authentication verifies who a user is; authorization defines what they can do. Managing users sits at that intersection. Acting as a security analyst, this lab ran the complete lifecycle for a new employee — all under sudo to respect authorization controls.

Provision & assign a primary group

A swapped argument order first returned "user 'research_team' does not exist" — a reminder that usermod -g expects group username, not the reverse. Corrected, it set research_team as the primary group.

bash
$ sudo useradd researcher9
$ sudo usermod -g research_team researcher9

Transfer file ownership

chown transferred project_r.txt to researcher9; ls -l confirmed the new owner while group and permissions stayed intact.

bash
$ sudo chown researcher9 project_r.txt
$ ls -l
# -rw-rw-r-- 1 researcher9 research_team 46 May 25 13:50 project_r.txt

Expand access, then offboard

A supplementary group was appended with -aG (the -a appends without removing existing membership; the flags are case-sensitive). A year later, userdel removed the account, leaving an orphaned personal group that groupdel cleaned up.

bash
$ sudo usermod -aG sales_team researcher9
$ sudo userdel researcher9
$ sudo groupdel researcher9

key takeaway

Access control is not a setting you configure once — it is a discipline you enforce continuously. The user lifecycle maps directly to least privilege: give access only to what is needed, only for as long as it is needed, then revoke it cleanly.
