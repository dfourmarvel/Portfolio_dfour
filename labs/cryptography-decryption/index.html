Cryptography in Linux: Breaking Two Layers

Recovering encrypted files through a classical Caesar cipher and modern AES-256-CBC — with the key hidden inside a hidden file.

tropensslAES-256-CBCPBKDF2Caesar cipherls -a

Every file in the analyst’s home directory had been encrypted. Recovery required three sequential operations: reading the encrypted listing, breaking a Caesar cipher hidden inside a dotfile, then using OpenSSL’s AES-256-CBC to decrypt the main data file.

Task 1 — Read the instructions

ls revealed Q1.encrypted, README.txt, and a caesar subdirectory. The README directed the analyst to a hidden file inside caesar.

Task 2 — Break the Caesar cipher

ls -a surfaced a hidden dotfile .leftShift3 — files beginning with a period are hidden from standard ls. Its contents were scrambled by a Caesar cipher with a left-shift of three. The tr command reversed the substitution, revealing the OpenSSL command needed for Task 3.

bash
$ cd caesar
$ ls -a
$ cat .leftShift3 | tr "d-za-cD-ZA-C" "a-zA-Z"

Task 3 — Decrypt with AES-256-CBC

Back in the home directory, the recovered command decrypted Q1.encrypted to Q1.recovered. The -pbkdf2 flag applied Password-Based Key Derivation Function 2, -a handled Base64, and the key — ettubrute — came from the Caesar cipher.

bash
$ cd ~
$ openssl aes-256-cbc -pbkdf2 -a -d -in Q1.encrypted \
    -out Q1.recovered -k ettubrute
$ cat Q1.recovered

key takeaway

Encryption is only as strong as the key management around it. The Caesar cipher fell the moment the shift was known; AES-256 held — but the password was sitting in a file one directory away. The algorithm is rarely the weakest link.

AES-256 is the same standard that protects patient records. Understanding how it works, and how its keys can be exposed, is the gap between a clinician who trusts encryption and one who can evaluate it.
