Filtering with Numbers and Dates in SQL

Reconstructing an incident timeline with comparison operators and BETWEEN across date, time, and event-ID ranges.

MariaDB> < >= <=BETWEEN … ANDDate/time filtering

Date thresholds (> vs >=)

Strict greater-than excluded the boundary date, returning 125 rows after 2022-05-09; greater-than-or-equal included it, expanding to 165. The one-character difference materially changes the result set — a detail that matters in incident scoping.

sql
SELECT * FROM log_in_attempts
WHERE login_date >= '2022-05-09';

Bounded windows (BETWEEN)

BETWEEN … AND narrowed the window to a three-day range (123 rows), then to the 06:00–07:00 login hour (15 rows, earliest at 06:01:31) — the kind of tight window that surfaces anomalous access.

sql
SELECT * FROM log_in_attempts
WHERE login_time BETWEEN '06:00:00' AND '07:00:00';

Numeric event-ID ranges

Filtering by numeric event_id (unquoted) with >= and BETWEEN 100 AND 150 pinpointed specific events while selecting only the columns needed to reduce output noise.

key takeaway

Numeric and date/time operators are the backbone of timeline reconstruction: 125 vs 165 rows on a single boundary, 67 after-hours logins refined to 15 in a target window. Precision here is precision in the investigation.
