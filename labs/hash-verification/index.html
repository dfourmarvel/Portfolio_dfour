Comparing Hash Values with Linux Tools

Two files that look identical on screen, and the SHA-256 workflow that proves they are not.

sha256sumcatcmp>> redirectionEICAR test string

A hash function is a one-way algorithm producing a fixed-length digest that uniquely represents an input’s contents — a single-bit change yields a completely different digest. This lab began with two files that printed the identical EICAR antivirus test string to the terminal, yet differed at the binary level.

Task 1 — Generate hashes

cat showed both files as visually identical. But sha256sum produced two completely different 64-character digests — the avalanche effect in action, exposing a difference invisible to the eye.

bash
$ sha256sum file1.txt
# 131f95c5...bdfd8267  file1.txt
$ sha256sum file2.txt
# 2558ba9a...f9ca017b  file2.txt

Task 2 — Persist and compare

Each digest was appended to its own file with the >> operator (a practical SOC pattern — hashes often need logging or feeding into automated pipelines), then compared byte-for-byte with cmp, which reports the exact position of the first divergence.

bash
$ sha256sum file1.txt >> file1hash
$ sha256sum file2.txt >> file2hash
$ cmp file1hash file2hash
# file1hash file2hash differ: char 1, line 1

key takeaway

Visual inspection of file contents is not integrity verification. A threat actor can swap a legitimate binary, preserve its readable output, and leave no obvious trace — unless you are hashing. sha256sum doesn’t care what a file looks like; it cares what the file is.
