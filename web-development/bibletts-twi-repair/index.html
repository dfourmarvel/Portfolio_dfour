BibleTTS Twi Transcript Repair

A side effect of building speech tools for Twi: found that a published open dataset had been silently corrupting Twi text since 2024, fixed it, and published the repair for anyone else using the same data.

Overview

BibleTTS is an open speech dataset used to train and evaluate speech recognition for a set of African languages, including Asante Twi. While preparing training data for a separate speech project, I noticed the Asante Twi transcripts read wrong — not mistranscribed, but missing letters in a pattern too consistent to be a typo.

The bug

Every transcript in the released Asante Twi set had ɛ (U+025B) and ɔ (U+0254) — two vowels that exist only in Twi's orthography, not in English — stripped out and replaced with spaces. Across a 1,500-file sample, the count was zero. A same-sized sample of the Ewe portion of BibleTTS, which doesn't use those characters as diacritics in the same way, contained 6,145 occurrences of ɔ in the same span — confirming the gap was specific to the Twi processing pipeline, not a fluke of the sample. The defect affected all ~21,600 Asante Twi transcripts and had gone unreported since the dataset's release; an open issue on the upstream repository had sat with no replies since March 2024.

The fix

Re-downloading doesn't help — the corruption is in the published transcript files themselves, not a download artifact. The fix is a verse-by-verse lookup against the Biblica USFM source text from ebible.org, restoring the correct characters verse by verse rather than attempting forced alignment or guesswork. The rebuild script threads its file reads — a single-threaded pass over 43,000 files was creeping toward an hour on my connection; threaded, it finishes in under a minute.

Publishing it

Repaired transcripts are published as an open dataset on Hugging Face under CC BY-SA 4.0, matching the license of both source datasets. Original and repaired text sit side by side per entry, so the change is auditable rather than a black-box replacement. I also posted the finding as a comment on the original GitHub issue, linking the dataset so anyone else building on BibleTTS's Twi data can pick up the fix without re-deriving it.

what I learned

This wasn't the project I set out to build — it was a bug I tripped over on the way to one. The instinct to keep going is strong when the actual goal is somewhere else, but a silently corrupted dataset sitting unfixed for two years is a bigger problem than my own timeline. Publishing the fix took an afternoon; leaving it broken would have cost every future user of that data a lot more.
