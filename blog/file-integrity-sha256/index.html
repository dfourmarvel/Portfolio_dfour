Two files. Same content. Different hashes.

Jun 11, 2026 file integrity google cybersecurity certificate lab

Two files. Same content on screen. Completely different hash values.

That's the scenario I worked through in this lab — and it's exactly the kind of deception a malicious program uses to hide in plain sight.

Here's what I did to expose the difference:

Used cat to display both files — they printed the exact same EICAR antivirus test string, indistinguishable to the naked eye

Ran sha256sum on each file — the digests were entirely different: 131f95c5... vs 2558ba9a...

Redirected both hash values into separate files using the >> operator

Used cmp for a byte-level comparison, which confirmed the mismatch at character 1, line 1

Key takeaway: visual inspection of file contents is not integrity verification. A threat actor can swap out a legitimate binary, preserve its readable output, and leave no obvious trace — unless you're hashing.

sha256sum doesn't care what the file looks like. It cares what the file is.
