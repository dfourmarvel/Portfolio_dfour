Applying filters to a Wireshark packet capture

Aug 13, 2026 network analysis google cybersecurity certificate lab

Applying display filters to a packet capture in Wireshark, as part of the Google Cybersecurity Certificate. My first lab with the tool.

The setup: a saved capture file, sample.pcap, holding 200 packets from a user who had browsed to opensource.google.com. Two hundred sounds manageable until you open it. ICMP, DNS, TCP, HTTP and SSH all interleaved, row after row, with no obvious place to start.

Display filters are the place to start. Filtering on one IP address cut the list from 200 packets to 16. Splitting that by direction separated what the server sent from what it received. Filtering on a MAC address instead returned every protocol that machine touched, which answers a different question: show me this interface, whatever it happens to be talking to. Filtering UDP port 53 surfaced the DNS lookup, which is where that IP address came from in the first place. Filtering TCP port 80 isolated the web request itself. One last filter searched the payload text rather than the headers.

Then the packet detail pane, one collapsible section per layer: frame, Ethernet, IP, TCP. Opening them in order is what turned encapsulation from a diagram I had read about into something I could read off a screen.

The filter is the analysis. Everything after it follows from asking one question at a time and knowing which field answers it.
