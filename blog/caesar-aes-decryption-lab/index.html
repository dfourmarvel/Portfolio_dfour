The key is hidden inside a cipher

Jun 8, 2026 cryptography google cybersecurity certificate lab

Your data is encrypted. The key is hidden inside a cipher. The cipher is hidden inside a hidden file. Go.

That was the setup for this lab — a simulated scenario where every file in the home directory had been locked, and the only way out was through two layers of cryptography: a classical Caesar cipher and a modern AES-256-CBC encrypted file.

Here is what I worked through:

  • Used ls and cat to explore the home directory and read the README instructions pointing toward a hidden file
  • Navigated into the caesar subdirectory and ran ls -a to surface the hidden dotfile .leftShift3
  • Read the scrambled ciphertext and applied a tr command to reverse the three-position left shift, recovering the plaintext OpenSSL command
  • Executed openssl aes-256-cbc with PBKDF2 key derivation to decrypt Q1.encrypted into Q1.recovered using the key ettubrute
  • Confirmed full decryption by reading the recovered file's hidden message

Key takeaway: encryption is only as strong as the key management around it. The Caesar cipher fell the moment the shift value was known. AES-256 held — but the password was sitting in a file one directory away. The algorithm is rarely the weakest link.

In medicine, patient data is protected by the same AES-256 standard that secured this lab file. Understanding how that cipher works — and how its keys can be exposed — is exactly the knowledge gap between a clinician who trusts encryption and one who can actually evaluate it.
