My first SQL lab

May 28, 2026 sql google cybersecurity certificate lab

Just completed my first SQL lab and honestly? It hits different when the queries actually work.

The lab simulated a real security analyst workflow — I was given access to an organization's database and tasked with two things:

  • Identify employee devices due for security updates
  • Investigate login attempts for suspicious activity

Here's what I actually did:

Used SELECT with specific columns (device_id, email_client, OS_patch_date) to filter only the data relevant to the update audit — no noise, just signal.

Queried the log_in_attempts table to check login locations, timestamps, and usernames. Spotted several after-hours logins (e.g. 03:05 AM, 01:30 AM) that would warrant deeper investigation in a real environment.

Applied ORDER BY on login_date and login_time together to reconstruct a chronological timeline of access events — a core technique in incident response.

The biggest takeaway? Even the most basic SQL commands have serious security implications. Knowing which columns to pull, and in what order to view them, can be the difference between catching a threat early and missing it entirely.

Filters, WHERE clauses, and JOIN queries are next — and I'm excited to keep going.
