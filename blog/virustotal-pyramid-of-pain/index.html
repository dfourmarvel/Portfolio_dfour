The password was in the same email as the attachment

Aug 19, 2026 malware analysis google cybersecurity certificate lab

1:11 p.m. An employee opens an email with a password-protected spreadsheet attached. The password is sitting right there in the same email. Two minutes later the file is open. Two minutes after that, multiple unauthorized executables appear on the machine, and by 1:20 the IDS is screaming.

Password-protecting your own malicious attachment and then handing over the key in the same message is either lazy social engineering or supreme confidence in the reader's trust. Judging by how many people open these, it works either way, mostly because it slips the file past the email gateway's automated scanning, which can't crack a password it was never given.

The investigation starts with a single SHA-256 hash pulled from the retrieved file, run through VirusTotal. 53 of 71 security vendors flag it outright. Community score: -292. Threat label: trojan.flagpro/fragtor. Three independent signals, all pointing the same direction, no real ambiguity.

From there it's a Pyramid of Pain exercise: work up from the hash to everything else this file touches. An MD5 sitting alongside the SHA-256 in the Details tab. A domain, a.sinkhole.yourtrap.com, flagged by 10 of 91 vendors. An IP address the malware genuinely contacted, flagged by exactly zero. A dropped host artifact. Two abused native Windows tools, cmd.exe and wmiprvse.exe, doing an attacker's work without either of them needing to be malicious software themselves. Classic living-off-the-land: use what's already trusted and already there. And three techniques mapped to MITRE's Privilege Escalation tactic, sitting at the top.

That IP address is the interesting part. Zero out of 91 vendors flagged it, and it's still evidence, not of innocence, but of how disposable IP infrastructure is to begin with. An attacker burns an IP and stands up another one before lunch. Rewriting the technique that got them privilege escalation in the first place takes a lot more than that, which is exactly why the pyramid puts TTPs at the top and IPs near the bottom. If you're only blocking indicators, you're only ever a few minutes ahead of the next rotation.
