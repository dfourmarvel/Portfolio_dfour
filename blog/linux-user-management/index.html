Linux user management as a security discipline

May 25, 2026 linux google cybersecurity certificate lab

Just completed a hands-on Linux user management lab as part of the Google Cybersecurity Certificate — and it reinforced something fundamental: access control isn't just a technical task, it's a security discipline.

The lab simulated a real-world scenario — onboarding a new employee, adjusting their access as their role evolved, and offboarding them when they left. Here's what I worked through:

Authentication vs. Authorization

Before touching a single command, the lab grounded me in the distinction between the two. Authentication confirms identity. Authorization defines what that identity can do. Managing users sits right at that intersection.

Commands used:

  • useradd — provisioned a new user account on the system
  • usermod -g — assigned a primary group (research_team)
  • chown — transferred file ownership to reflect new responsibilities
  • usermod -aG — appended a secondary group (sales_team) without overwriting existing group membership
  • userdel + groupdel — cleanly removed the user and the orphaned personal group left behind

Principle of Least Privilege in practice

Every step was a deliberate access decision — not just "add the user" but "what should this user be able to access, and only that." When the role changed, the permissions changed. When they left, access was fully revoked.

This is one lab in a longer journey, but each one is building the foundation I need to work in defensive security.
